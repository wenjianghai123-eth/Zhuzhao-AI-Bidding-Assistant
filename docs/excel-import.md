# Excel 导入

## 目标与范围

第一阶段支持 `.xlsx`，导入以下原始输入数据：

1. 项目参数及规则；
2. 候选单位；
3. 公共季度履约记录。

每次成功导入创建一个新项目。清标和定标历史计算结果不会写入 `QingbiaoScenario`、`QingbiaoResult`、`DingbiaoScenario` 或 `DingbiaoResult`。

## 原《投标伴侣方案设计.xlsx》结构分析

已分析的工作簿包含四张工作表：

| 工作表 | 原始结构 | 当前导入策略 |
| --- | --- | --- |
| 参数设置 | 项目参数采用标签/值布局；候选单位采用表格布局 | 导入项目参数、候选单位；清理单位名称首尾空格 |
| 履约信息 | 每行一家企业和一个专业，季度分数横向排列 | 将每个非空季度单元格展开为一条 `CompanyPerformance` 行式记录；忽略“加权平均分”列 |
| 清标测算 | 场景选择、公式说明和旧测算结果模板 | 仅识别并提示，不导入任何旧计算结果 |
| 定标测算 | N=5/4/3、M值公式说明和旧预测结果模板 | 仅识别并提示，不导入任何旧计算结果 |

原工作簿本身是方案设计模板，多个单元格仍为“录入”“选择”等占位内容。解析器会把这些内容识别为错误，而不会把模板文字写入数据库。

## 导入流程

```text
上传 .xlsx
  -> 服务端解析工作簿
  -> 自动识别并展示字段映射
  -> 项目/候选单位/履约数据预览
  -> 逐行错误与数据库冲突检查
  -> 用户明确确认
  -> 重新解析并校验预览摘要
  -> 单个 Prisma 事务写入
```

上传和预览阶段没有数据库写入。确认导入必须携带同一文件及字段映射生成的 SHA-256 预览摘要；文件或映射发生变化后必须重新预览。

## 识别与数值规则

- 项目类型支持幕墙、装修、总包、实验室，多类型项目可在一个单元格中填写。
- 候选单位名称和履约单位名称统一清理首尾空格。
- 候选单位名称在同一工作簿内重复时，错误信息同时给出当前行与首次出现行。
- 金额、分数和比例统一转换为十进制字符串后再进入仓储层。
- 净下浮率和定标抽值遵循现有界面规则：普通数字按百分数输入，例如 `10` 表示 `10%`；Excel 百分比格式或带 `%` 文本按其百分比值读取。
- 履约季度列支持 `24年4季度平均分`、`2024年4季度平均分`、`2024Q4` 等形式。
- 数字、必要字段、项目类型和季度无法识别时，错误包含工作表、Excel 行号和单元格位置。
- 已存在的同企业、同专业、同年份、同季度履约记录不会被覆盖；冲突会阻止整批导入。

## 原子性

确认阶段先在事务内重新检查履约唯一键，再创建项目、规则、候选单位和履约记录。任何冲突或数据库错误都会回滚整个事务，不保留部分项目或部分履约记录。

## 代码位置

- 导入页面：`src/app/(dashboard)/imports/excel`
- API：`src/app/api/imports/excel`

## 验证

```bash
pnpm test
pnpm verify:excel-import
```

`verify:excel-import` 会创建隔离的验收数据，验证成功导入以及履约冲突时不产生部分项目，随后清理验收数据。
