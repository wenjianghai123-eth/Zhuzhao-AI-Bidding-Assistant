## 4. 履约平均规则差异

### Excel 说明

Excel 将履约来源描述为“最近12季度加权平均分”，但没有提供季度权重、分类等级权重或时间衰减规则。

### 当前程序

`docs/calculation-rules.md` 明确采用临时规则：每个项目类型最近12季度等权平均，多项目类型再等权平均；缺少任一项目类型时阻断清标。

### 差异与影响

由于 Excel 没有可执行的权重，当前无法计算另一组权威 Excel 履约平均值。若未来确认权重不是等权，则会影响：

1. 履约平均分；
2. 履约得分；
3. 清标综合得分和最终排名；
4. 定标 Top N 入围名单；
5. 定标 K1、M、预测中标单位和模拟中标率。

本次没有修改现有等权规则。

## 5. 定标公式对照

### Excel 公式

```text
dingbiaoK1 = 当前 Top N 单位净下浮率平均值

M = (dingbiaoK1 + finalDrawValue)
    / 100
    × (最高投标限价 - 不可竞争费)
    + 不可竞争费

difference = abs(投标总价 - M)
```

差额最小者为预测中标单位；差额相同时低报价优先。同一 N 下我方中标次数除以 3 为模拟中标率。

### 当前 domain 公式

`calculateDingbiaoK1()`、`calculateFinalBenchmarkPrice()`、`rankDingbiaoCandidates()` 和 `calculateSimulationWinRate()` 与上述文字公式一致，前提是 `dingbiaoK1` 与 `finalDrawValue` 以“百分点”传入，例如 82% 传 `82`，1% 传 `1`。

### 当前 Web 端到端传值差异

现有表单和数据库按小数比例保存百分比：

- 82% 保存为 `0.82`；
- 1% 保存为 `0.01`。

仓储当前把这些小数比例直接传给 domain，domain 又执行 `/100`。这会造成二次缩放。公式文本没有变化，但端到端输入单位不一致。

黄金场景对照：

| N | 指标 | Excel/百分点输入 | 当前 Web 存储值直接输入 |
| ---: | --- | --- | --- |
| 5 | 定标 K1 | 81.8 | 0.818 |
| 5 | 三个 M | 836.2 / 845.2 / 854.2 | 107.362 / 107.452 / 107.542 |
| 5 | 预测中标单位 | c3 / c3 / c4 | c5 / c5 / c5 |
| 5 | 我方模拟中标率 | 66.666666666666666667% | 0% |
| 4 | 定标 K1 | 81 | 0.81 |
| 4 | 三个 M | 829 / 838 / 847 | 107.29 / 107.38 / 107.47 |
| 4 | 预测中标单位 | c2 / c3 / c3 | c5 / c5 / c5 |
| 4 | 我方模拟中标率 | 66.666666666666666667% | 0% |
| 3 | 定标 K1 | 83.333333333333333333 | 0.83333333333333333333 |
| 3 | 三个 M | 850 / 859 / 868 | 107.5 / 107.59 / 107.68 |
| 3 | 预测中标单位 | c3 / c3 / c3 | c2 / c2 / c2 |
| 3 | 我方模拟中标率 | 100% | 0% |

受影响结果：定标 K1 的显示值、M、所有单位与 M 的差额、定标排名、预测中标单位、模拟中标率以及所有基于定标结果的决策分析。

本次没有修改 domain、表单转换或仓储映射。需要业务确认以下一种统一口径后再修复：

1. domain 使用百分点：在应用边界把数据库小数比例乘以 100 后再调用现有 Excel 公式；或
2. domain 使用小数比例：调整唯一 M 函数的单位契约及公式表达，并同步更新测试与文档。

无论采用哪一种，UI 中的 82% 都必须只缩放一次。
