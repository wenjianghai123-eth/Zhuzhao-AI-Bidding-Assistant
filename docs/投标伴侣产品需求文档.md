## 1. 文档说明

本文档将原 Excel 中的字段、计算说明和报表要求转换为可评审的产品需求。原文件目前是静态方案原型，没有实际公式、数据校验或可执行按钮。

文中标记为“待确认”的内容不得直接作为生产计算规则。尤其是定标 M 值、K2 的作用方式和百分比存储口径，须在研发计算引擎前完成业务确认。

## 2. 产品背景与目标

### 2.1 背景

投标测算涉及项目限价、不可竞争费、候选单位报价、历史履约、主客观评分、清标抽取值和定标抽值。现有方案通过 Excel 描述计算逻辑，但缺少结构化数据管理、自动测算、异常校验和稳定的结果输出。

### 2.2 产品目标

建设一套投标情景测算工具，实现：

1. 集中维护项目、候选单位、评分参数和履约数据。
2. 模拟清标 K2=0%、1%、2%、3% 四种情景。
3. 自动计算候选单位履约得分、报价得分、清标总分和排名。
4. 基于清标结果模拟 N=5、N=4、N=3 三种入围规模。
5. 使用三个定标抽值预测中标单位。
6. 统计单位模拟中标率，并识别我方单位的有利参数组合。
7. 生成可复核的清标、定标明细和结论。

### 2.3 成功标准

- 同一组输入在重复计算时得到完全一致的结果。
- 每个输出结果均可追溯到输入数据、计算公式和中间值。
- 业务人员无需手工复制公式即可新增候选单位或履约季度。
- 系统能够阻止缺少必要参数的测算。
- 边界条件和并列情况有确定、可测试的处理规则。

## 3. 范围

### 3.1 MVP 范围

- 项目基本信息管理
- 清标、定标参数管理
- 候选单位管理
- 季度履约数据管理
- 最近 12 季度履约结果计算
- 四种清标情景配置和测算
- 三种入围规模的定标预测
- 模拟中标率及我方单位专项分析
- 测算明细、结论查看与导出

### 3.2 暂不纳入 MVP

原 Excel 未定义以下需求，暂不纳入 MVP：

- 自动解析招标文件或投标文件
- AI 生成投标内容
- 自动对接外部履约系统
- 电子签章和正式审批流
- 多组织、复杂角色权限
- 自动向第三方平台下发报告

如需上述能力，应单独补充业务场景、数据源和验收标准。

## 4. 用户与使用场景

原 Excel 未定义用户角色。MVP 暂按“业务测算人员”单角色设计，权限体系作为后续需求。

主要场景：

1. 创建项目并设置最高投标限价等基础参数。
2. 录入候选单位报价和评分数据。
3. 关联候选单位的历史履约数据。
4. 配置四种清标情景并生成前五名预测。
5. 选择清标情景，模拟不同入围数量下的中标单位。
6. 查看各单位模拟中标率和我方单位的最有利组合。

## 5. 名词定义

| 名词 | 定义 |
|---|---|
| 最高投标限价 | 项目允许的最高投标总价，单位万元 |
| 不可竞争费 | 不参与价格竞争的固定费用，单位万元 |
| 可竞争金额 | 最高投标限价减去不可竞争费 |
| 净下浮率 | 投标报价相对于可竞争金额的下浮比例；精确定义待确认 |
| 清标 K1 | 根据情景平均报价折算得到的下浮率 |
| 清标 K2 | 原方案中的 0%～3%情景值；具体数学作用待确认 |
| 定标 K1 | 当前入围单位净下浮率的平均值 |
| 定标抽值 | 参数设置中录入的三个定标调整值 |
| M 值 | 定标阶段用于与单位投标总价比较的目标价格 |
| N | 定标阶段入围单位数量，取 5、4 或 3 |

## 6. 整体业务流程

```text
创建项目并设置参数
        ↓
录入候选单位及报价、评分
        ↓
维护或关联季度履约数据
        ↓
配置四种清标 K2 情景
        ↓
执行清标测算并生成四组排名
        ↓

```

## 8. 详细功能需求

### 8.1 项目与参数

#### FR-PROJ-001 创建和编辑项目

系统应支持维护以下字段：

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| 项目名称 | 文本 | 是 | 同一业务范围内是否允许重名待确认 |
| 最高投标限价 | 金额 | 是 | 大于0，单位万元 |
| 不可竞争费 | 金额 | 是 | 大于等于0，且小于最高投标限价 |
| 项目类型 | 多选枚举 | 是 | 幕墙、装修、总包、实验室，至少选择1项 |

修改已完成测算的项目参数时，系统应提示原测算结果将失效，并要求重新测算。

#### FR-PROJ-002 清标参数

系统应支持维护：

- 总投标报价满分
- 排名递减扣分值
- 同类业绩分值配置
- 其他主客观分值配置

原 Excel 第6、7行存在重复字段，字段含义须在原型评审时确认。

#### FR-PROJ-003 定标参数

系统应支持维护三个定标抽值。界面以百分比显示，内部推荐统一使用小数比例存储，例如 1%存储为0.01。

### 8.2 候选单位

#### FR-BID-001 候选单位维护

系统应支持新增、编辑和删除候选单位，字段如下：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| 单位ID | 系统标识 | 是 | 用于稳定关联履约数据 |
| 单位名称 | 文本/单位库选择 | 是 | 同一项目内不可重复 |
| 投标总价 | 金额 | 是 | 单位万元 |
| 净下浮率 | 百分比 | 是 | 可录入或根据报价自动计算，方式待确认 |
| 商标优 | 数值 | 待确认 | 是否参与总分待确认 |
| 技术优 | 数值 | 待确认 | 是否参与总分待确认 |
| 同类业绩 | 数值 | 是 | 不得超过对应评分上限 |
| 其他主客观分 | 数值 | 是 | 不得超过对应评分上限 |

#### FR-BID-002 候选单位校验

- 投标总价必须为非负数。
- 是否允许投标总价等于或高于最高投标限价，待业务确认。
- 得分字段不得超过相应满分，不得为负数。
- 删除已参与测算的单位后，原测算结果应标记失效。

### 8.3 履约管理

#### FR-PERF-001 履约记录维护

履约记录按以下粒度存储：

```text
单位ID + 项目类型 + 年度 + 季度
```

字段包括单位、项目类型、分类分级等级、年度、季度、季度履约分。

同一单位、项目类型、年度和季度只能存在一条有效记录。

#### FR-PERF-002 最近12季度履约结果

系统应按时间倒序获取最近12个季度的有效记录并计算履约结果。

以下规则待业务确认：

- 12个季度是否等权。
- 不足12个季度是否按已有季度计算。
- 缺失季度是否按0分、忽略或禁止测算。
- 越近季度是否使用更高权重。

#### FR-PERF-003 多项目类型汇总

项目选择多个类型时，应先取得同一单位在各类型下的最近12季度结果，再计算跨类型结果。跨类型是否等权待确认。

### 8.4 清标情景配置

#### FR-CLEAR-001 四种情景

系统应展示 K2=0%、1%、2%、3%四种清标情景。每种情景支持从当前项目候选单位中多选参与单位。

每种情景的最少选择数量待确认。

#### FR-CLEAR-002 测算按钮状态

只有以下条件全部满足时才能执行清标测算：

- 项目基本信息完整且校验通过。
- 清标参数完整。
- 至少存在满足要求的候选单位。
- 所需履约数据满足业务规则。
- 四种 K2 情景均配置完成。

否则按钮禁用，并显示具体缺失项。

### 8.5 清标计算

#### FR-CLEAR-003 履约原始结果

系统按单位ID和项目类型取得履约结果。多类型项目按 FR-PERF-003 汇总。

#### FR-CLEAR-004 履约得分

原方案公式：

```text
履约得分 = 10 × (A - AMin) / (AMax - AMin)
```

- A：当前单位履约结果
- AMax：本次参与清标单位中的最高履约结果
- AMin：本次参与清标单位中的最低履约结果

当 AMax=AMin 时的得分规则待确认，系统不得直接产生除零错误。

#### FR-CLEAR-005 情景平均报价及清标 K1

对每个 K2 情景计算所选单位投标总价的平均值 B。

原方案中的清标 K1 为：

```text
K1 = [1 - (B - 不可竞争费)
          / (最高投标限价 - 不可竞争费)]
```

界面按百分比显示。

K2 如何参与 B、K1或评审基准价计算尚未定义，属于阻塞研发的待确认项。

#### FR-CLEAR-006 报价差值及排名

对每个情景计算所有候选单位与情景平均报价 B 的差值：

```text
报价差值 = ABS(单位投标总价 - B)
```

按差值从小到大排名。差值相同的并列和破同分规则待确认。

#### FR-CLEAR-007 报价得分

```text
报价得分 = 总投标报价满分
           - (报价排名 - 1) × 排名递减扣分值
```

排名第一取得报价满分。是否以0分为最低分待确认。

#### FR-CLEAR-008 清标总分

原方案中的总分为：

```text
清标总分 = 履约得分
           + 同类业绩得分
           + 其他主客观分
           + 当前情景报价得分
```

商标优和技术优是否计入总分待确认。总分小数精度及同分排序规则待确认。

#### FR-CLEAR-009 清标排名与入围结果

系统应分别生成四种情景的：

- 平均报价 B
- 清标 K1
- 单位履约结果及履约得分
- 单位报价差值和排名
- 单位报价得分
- 单位清标总分和总排名
- 排名前五的单位

候选单位不足五家时的处理方式待确认。

#### FR-CLEAR-010 清标结论

系统应自动生成四种清标抽取值情景的前五单位结论。结果包含我方单位时，应在界面和导出报告中突出显示。

单位识别必须使用单位ID，不得只依赖名称文本完全匹配。

### 8.6 定标预测

#### FR-AWARD-001 选择清标情景

用户选择 K2=0%、1%、2%或3%中的一个已完成清标测算的情景。

#### FR-AWARD-002 形成入围方案

- N=5：取所选清标情景总分前5名。
- N=4：取所选清标情景总分前4名。
- N=3：取所选清标情景总分前3名。

原 Excel 中 N=4、N=3仍写“前5家”，本需求按相应 N 值修正。

#### FR-AWARD-003 定标 K1

每种 N 方案分别计算当前入围单位净下浮率平均值：

```text
定标K1 = SUM(入围单位净下浮率) / N
```

#### FR-AWARD-004 M 值

原 Excel 公式为：

```text
M值 = (定标K1 + 定标抽值) / 100
      × (最高投标限价 - 不可竞争费)
      + 不可竞争费
```

该公式与“净下浮率”定义可能相反，且存在重复除以100风险。在业务确认前只保留为待确认公式，不得进入生产计算。

推荐评审的候选口径为：

```text
M值 = [1 - (定标K1 + 定标抽值)]
      × (最高投标限价 - 不可竞争费)
      + 不可竞争费
```

最终以业务方书面确认和验算样例为准。

#### FR-AWARD-005 中标判定

```text
差额 = ABS(单位投标总价 - M值)
```

- 差额最小的单位预测中标。
- 多家单位差额相同时，投标总价最低者优先。
- 差额和投标总价均相同时的最终规则待确认。

#### FR-AWARD-006 九组预测

每次定标测算产生：

```text
3种入围规模 × 3个定标抽值 = 9组结果
```

每组展示入围单位、定标K1、定标抽值、M值、单位差额、差额排名和预测中标单位。

### 8.7 结果与报表

#### FR-REPORT-001 中标率

```text
中标率 = 单位预测中标次数 / 纳入统计的情景总数
```

统计范围待确认：

- 口径A：当前清标 K2 下的9组预测。
- 口径B：四种清标 K2 下的全部36组预测。

#### FR-REPORT-002 我方单位专项分析

系统应展示：

- 我方单位在四种清标情景中的排名和是否入围。
- 在每种 N 和定标抽值组合下是否预测中标。
- 中标率最高的清标 K2、N和定标抽值组合。

#### FR-REPORT-003 测算结果追溯

结果页和导出报告至少包含：

- 项目基础信息
- 本次计算使用的参数快照
- 候选单位输入数据快照
- 履约原始结果及评分中间值
- 清标四情景明细
- 定标九组预测明细
- 清标、定标文字结论
- 测算时间和测算版本

导出格式（Excel、PDF或两者）待确认。

## 9. 状态与失效机制

建议测算记录使用以下状态：

| 状态 | 含义 |
|---|---|
| 草稿 | 基础数据尚未完成 |
| 可测算 | 必填数据和情景配置已通过校验 |
| 已测算 | 已生成当前输入版本的结果 |
| 已失效 | 输入或参数在测算后发生变化，需重新计算 |

修改项目参数、候选单位、报价、评分、履约结果或情景单位集合后，相关结果应自动标记失效。

## 11. 非功能需求

### 11.1 精度

- 金额内部计算精度至少保留到元，界面按万元展示。
- 百分比内部使用统一的小数比例。
- 中间值不得提前四舍五入；只在展示层格式化。
- 排名必须使用未格式化的原始精度值。

最终展示小数位数待业务确认。

### 11.2 可解释性

每个得分、排名和中标结果必须能查看计算明细，包括公式、输入值、中间值和最终值。

### 11.3 一致性

测算应在一个固定参数快照中完成。测算过程中若基础数据变化，本次结果不得混用新旧数据。

### 11.4 性能

单项目100家候选单位、20年季度履约数据规模下，单次清标和定标测算建议在3秒内完成。

### 11.5 安全与审计

- 不得保留对个人本地路径或外部工作簿的依赖。
- 记录参数和数据的修改时间。
- 记录每次测算的执行人、执行时间和版本。

## 12. 核心验收场景

### AC-01 正常清标

给定完整项目参数、至少5家单位及有效履约数据，配置四种 K2 情景后可以测算，并为每种情景生成完整排名和前五结论。

### AC-02 前置校验

任一 K2 情景未配置时，清标按钮不可执行，并提示缺失情景。

### AC-03 履约相同

所有候选单位履约结果相同时，系统按已确认规则给分，不出现除零错误。

### AC-04 报价差值相同

两家单位报价差值相同时，系统按已确认的并列规则得到稳定、可重复的排名。

### AC-05 定标预测

选择任一清标 K2 情景后，系统分别形成 N=5、N=4、N=3方案，并对三个定标抽值生成9组预测。

### AC-06 中标破同分

多家单位与 M 值差额相同时，报价更低的单位被判定为中标。

### AC-07 结果失效

修改已测算项目的报价后，旧结果立即标记失效，重新测算后生成新版本且历史结果可追溯。

### AC-08 我方单位突出显示

我方单位进入清标前五或预测中标时，界面和导出报告均按要求突出展示。

## 14. 需求评审出口条件

满足以下条件后，计算引擎任务才能进入开发：

1. BQ-01至BQ-11均有书面结论。
2. 业务方提供至少一套完整的脱敏验算样例。
3. 样例包含清标四情景和定标九组的人工期望结果。
