# 烛照AI投标助手 MVP 最终验收

## 1. 验收结论

MVP 的项目录入、候选单位、履约数据、清标、定标、决策分析和结果持久化主流程已经贯通。自动验收从一个独立、完全空白的 SQLite 数据库开始，实际应用仓库迁移，并通过现有 Server Actions 和 Application Services 完成全部数据写入与测算。

技术质量门禁通过，但当前只能判定为“技术流程验收通过，定标业务口径有条件通过”。净下浮率、定标抽值和 M 公式之间的单位语义仍需业务确认；在确认并修复前，定标预测及其衍生决策数据不能作为正式投标决策依据。

## 2. 已实现功能

- 项目列表、项目创建、项目概览和参数编辑。
- 最高投标限价、不可竞争费、项目类型、清标参数和三个定标抽值的校验与持久化。
- 候选单位新增、编辑、删除、唯一我方单位设置和重复单位校验。
- 公共履约数据库 CRUD、搜索与筛选。
- 单专业、多专业最近 12 季度履约平均及缺失专业提示。
- K2=0、1、2、3 四种清标场景的独立参考单位选择、计算、排名、Top5 和事务保存。
- 从已保存清标结果选择 K2，生成 N=5、N=4、N=3 与三个定标抽值组成的 3×3 定标矩阵。
- 定标明细、预测中标单位和模拟中标率展示与事务保存。
- 决策分析指标、清标竞争力、排名变化、定标矩阵、竞争对手统计和规则文本总结。
- Excel 项目参数、候选单位和履约数据的预览确认式导入。
- Loading、Skeleton、EmptyState、ErrorState、Toast、ConfirmDialog、重复提交防护和统一数值格式化。
- 项目不存在、参数不完整、履约缺失、候选不足、清标未完成等异常状态处理。

## 4. 已确认规则

### 4.1 数据与校验

- 最高投标限价必须大于 0。
- 不可竞争费必须大于等于 0，且必须小于最高投标限价。
- 项目至少选择一种项目类型。
- 一个项目内候选单位名称唯一，且最多只有一家我方单位。
- 履约数据使用“企业 + 项目类型 + 年份 + 季度”行式结构和唯一约束。
- 金额、比例、分数和公式中间值使用十进制字符串及 `decimal.js`，排名使用未舍入值。

### 4.2 清标

- 四个固定场景使用 `qingbiaoK2=0/1/2/3` 标识。
- `B = 场景所选候选单位投标总价平均值`。
- `qingbiaoK1 = [1-(B-不可竞争费)/(最高投标限价-不可竞争费)]×100`。
- 履约得分使用 Min-Max 归一化至 0～10；所有履约平均相同时统一记 10 分。
- 任一候选单位缺少项目所需专业履约数据时阻断整个清标计算，不按 0 分处理。
- 报价差额按 `abs(Pi-B)` 计算；同差额时低报价优先，再按候选 ID 稳定排序。
- 报价得分为 `总投标报价分值-(报价排名-1)×排名递减扣分值`。
- 综合得分只包含履约得分、同类业绩、其他主客观分和报价得分；商标优、技术优不计入。
- 综合得分并列时低报价优先，再按候选 ID 稳定排序。

### 4.3 定标与分析

- 从所选清标 K2 的最终排名中分别取得 Top5、Top4、Top3。
- 每个 N 独立计算入围单位净下浮率平均值 `dingbiaoK1`。
- 三个定标抽值与三个 N 正常形成 9 个模拟场景。
- 与 M 差额最小者为预测中标单位；并列时低报价优先，再按候选 ID 稳定排序。
- “模拟中标率”是同一 N 下我方在三个离散抽值场景中的中标次数除以 3，不表示统计学真实中标概率。
- 决策分析只读取已保存的清标、定标结果，不重新执行另一套公式。

完整公式与边界规则见 `docs/calculation-rules.md`。

## 5. 待业务确认规则

1. **定标百分比单位与 M 公式语义。** 当前数据库把 10% 保存为 `0.10`、1% 保存为 `0.01`，Excel 文字公式却按 10、1 这样的百分点输入并再除以 100。当前端到端会发生二次缩放，影响定标 K1、M、与 M 差额、预测中标单位、模拟中标率和决策分析。业务需确认 domain 使用百分点还是小数比例，再统一边界。
2. **最近 12 季度“加权平均”权重。** 当前没有业务权重表，MVP 临时采用季度等权平均，多项目类型之间也等权平均。
3. **清标 K2 的进一步数学含义。** 当前 K2 是四个场景标识，场景通过不同参考单位组合改变 B；尚未确认 K2 是否还应直接进入其他公式。
4. **并列排名规则。** Excel 未给出完整并列规则，MVP 使用低报价优先、候选 ID 稳定排序。
5. **正式报表舍入精度。** UI 金额和百分比统一显示两位小数，计算中间值不舍入；正式报告精度仍需签字确认。
6. **Excel 黄金样例。** 原工作簿主要是文字方案和占位数据，缺少可执行公式缓存和完整数值样例；需要业务提供冻结的真实验收样本。

## 7. 已知限制

- 当前定标百分比单位问题会导致 M 及后续预测偏离 Excel 百分点口径，是正式业务使用前必须解决的高优先级限制。
- 当前会话未提供可用浏览器实例，因此本轮无法由自动化代理完成视觉点击、Toast、Dialog 和响应式布局验收；应按第 11 节执行一次人工浏览器验收。
- 履约数据目前使用企业名称关联，没有独立 Company 主数据 ID；企业更名可能导致历史匹配失败。
- SQLite 适用于 MVP 单机/小规模部署，不代表并发生产数据库方案。
- 结果保存使用当前版本覆盖语义，尚无面向用户的完整历史版本管理。
- 报告页目前是功能占位，不生成正式报告。

## 9. 如何启动项目

首次运行：

```powershell
pnpm install
Copy-Item .env.example .env
pnpm db:deploy
pnpm dev
```

浏览器打开终端输出的地址，通常为 <http://127.0.0.1:3000/projects>。如果 3000 端口已占用，Next.js 会提示实际端口。

已有依赖和数据库时只需：

```powershell
pnpm dev
```

## 10. 如何初始化数据库

空数据库验收不要运行 seed：

```powershell
Copy-Item .env.example .env
pnpm db:deploy
```

`DATABASE_URL` 默认指向 `file:./dev.db`。若需要示例项目，再显式执行：

```powershell
pnpm db:seed
pnpm db:verify
```

不要通过删除正在使用的生产数据库来“初始化”。需要重新验收时，应设置一个新的 SQLite 文件路径后执行 `pnpm db:deploy`，或直接运行隔离的 `pnpm test:acceptance`。

## 11. 如何运行测试

完整质量门禁：

## 12. 如何完成一次完整人工验收

### 12.1 准备空库

为人工验收设置一个新的数据库文件，例如在 `.env` 中使用：

```dotenv
DATABASE_URL="file:./mvp-manual-acceptance.db"
```

然后执行：

```powershell
pnpm db:deploy
pnpm dev
```

不要执行 seed。打开 `/projects`，确认项目列表显示“暂无项目”。

### 12.2 创建项目和参数

进入“新建项目”，录入：

| 字段 | 验收值 |
| --- | --- |
| 项目名称 | MVP最终验收项目 |
| 最高投标限价 | 10000 万元 |
| 不可竞争费 | 500 万元 |
| 项目类型 | 幕墙 |
| 总投标报价分值 | 60 |
| 排名递减扣分值 | 2 |
| 定标抽值1/2/3 | 0% / 1% / 2% |

先尝试把最高限价改为 500，确认页面阻止提交并提示“最高投标限价必须大于不可竞争费”；恢复 10000 后保存。刷新参数页，确认所有数据仍存在。

### 12.3 添加候选和履约

依次添加以下 6 家候选单位；商标优、技术优均填 1：

| 单位 | 投标总价（万元） | 净下浮率 | 同类业绩 | 其他分 | 履约评分 |
| --- | ---: | ---: | ---: | ---: | ---: |
| MVP验收甲公司 | 7850 | 10.25% | 6 | 3 | 82 |
| MVP验收乙公司 | 7920 | 10.75% | 7 | 4 | 86 |
| MVP验收丙公司 | 7990 | 11.25% | 8 | 5 | 90 |
| MVP验收丁公司 | 8060 | 11.75% | 7.5 | 4.5 | 88 |
| MVP验收戊公司 | 8130 | 12.25% | 6.5 | 3.5 | 84 |
| MVP验收己公司 | 8200 | 12.75% | 6 | 3 | 80 |

将“MVP验收甲公司”设置为我方单位，确认只有一条“我方”标记。

进入履约数据库，为每家公司各添加一条：项目类型“幕墙”、分类等级“A”、年份 2026、季度 Q2、评分使用表中值。尝试重复录入同公司同专业同季度，确认系统阻止保存。

### 12.4 执行清标

进入项目清标页，分别配置：

- K2=0：选择全部 6 家作为 B 的参考单位。
- K2=1：选择甲、乙、丙。
- K2=2：选择丁、戊、己。
- K2=3：选择乙、丁、己。

确认四组未全部设置时按钮禁用；完成后执行清标。逐个 Tab 检查：B、清标 K1、我方排名、Top5 状态、6 家最终排名。确认四场景汇总和四张 Top5 卡片存在。刷新页面，确认选择和结果仍存在。

### 12.5 执行定标和分析

进入定标页，选择清标 K2=1 并执行预测。检查：

- N=5、N=4、N=3 均为可模拟。
- 每个 N 均有抽值1、抽值2、抽值3。
- 点击每个场景可以查看入围单位、报价、净下浮率、定标 K1、M、与 M 差额和预测中标单位。
- 顶部显示我方单位、清标排名和三个 N 的模拟中标率。

进入决策分析，检查顶部指标、4 行清标竞争力、排名变化图、9 行定标竞争力、竞争对手统计、最佳场景和两段规则总结。

最后分别刷新清标、定标、决策分析页面，确认没有回到空状态，且项目仍有 6 家候选、4 个清标场景和 9 个定标场景。

人工验收定标结果时必须同时记录第 5 节的比例单位待确认问题，不应把当前预测中标单位作为正式业务结论。
