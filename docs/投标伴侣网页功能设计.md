# 投标伴侣网页功能设计

## 1. 设计目标

将《投标伴侣方案设计.xlsx》的四个 Sheet 转换为可持续维护、可追溯、可执行测算的 Web 功能。

网页不照搬 Excel 的横向大表，而是拆分为“项目工作台 + 分步业务页面”，同时保留业务人员熟悉的表格录入和结果对比方式。

设计原则：

1. 输入、计算和结果分层，避免用户误改公式。
2. 每个计算结果可以查看来源和中间值。
3. 上游数据变化后，下游结果自动失效。
4. 单位、季度、情景采用结构化数据，不把多个值塞进一个单元格。
5. 计算规则使用版本管理，未确认的规则不得进入正式测算。

## 2. 产品形态

- 终端：桌面端 Web 优先。
- 推荐内容宽度：1440px及以上。
- 移动端：MVP仅支持查看项目状态和结果，不提供复杂表格编辑。
- 主操作对象：项目。
- MVP用户：业务测算人员；角色权限后续扩展。

## 3. 信息架构

```text
投标伴侣
├── 项目列表
│   ├── 新建项目
│   └── 项目工作台
│       ├── 项目概览
│       ├── 参数设置
│       ├── 候选单位
│       ├── 履约信息
│       ├── 清标测算
│       ├── 定标预测
│       ├── 结果报告
│       └── 测算历史
├── 履约数据库
│   ├── 单位管理
│   └── 季度履约记录
└── 系统设置
    ├── 项目类型
    ├── 计算规则版本
    └── 用户与权限（后续）
```

## 4. 全局页面框架

```text
┌─────────────────────────────────────────────────────────────┐
│ Logo 投标伴侣             项目名称/全局搜索      用户菜单   │
├──────────────┬──────────────────────────────────────────────┤
│ 项目概览     │ 面包屑 / 页面标题                    操作区  │
│ 参数设置     ├──────────────────────────────────────────────┤
│ 候选单位     │                                              │
│ 履约信息     │                 页面内容                     │
│ 清标测算     │                                              │
│ 定标预测     │                                              │
│ 结果报告     │                                              │
│ 测算历史     │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

全局规则：

- 左侧菜单展示当前项目各步骤状态：未完成、可测算、已测算、已失效。
- 页面顶部固定展示项目名称、项目类型和当前测算版本。
- 金额统一显示“万元”，比例统一显示“%”。
- 输入框只负责录入，计算字段使用只读样式，并提供“查看计算过程”。
- 页面离开前若有未保存数据，应提示用户。

## 5. 项目主流程

```text
新建项目
  ↓
完成参数设置
  ↓
录入候选单位
  ↓
关联履约信息
  ↓
配置并执行清标
  ↓
执行定标预测
  ↓
查看和导出报告
```

项目工作台顶部显示步骤条：

```text
① 参数设置 → ② 候选单位 → ③ 履约信息
→ ④ 清标测算 → ⑤ 定标预测 → ⑥ 结果报告
```

步骤条用于展示状态，不强制用户只能顺序打开页面；执行计算时必须满足前置校验。

## 6. 页面功能设计

### 6.1 项目列表

#### 页面目标

集中查看和进入投标测算项目。

#### 页面组成

- 搜索：项目名称。
- 筛选：项目类型、项目状态、更新时间。
- 列表字段：项目名称、项目类型、最高投标限价、候选单位数、当前阶段、测算状态、更新时间、操作人。
- 操作：新建、进入、复制项目、归档。

#### 新建项目

点击“新建项目”打开抽屉或独立页面，填写：

- 项目名称
- 最高投标限价
- 不可竞争费
- 项目类型，多选

保存后进入项目工作台的“参数设置”。

#### 状态标签

| 状态 | 显示含义 |
|---|---|
| 草稿 | 基础数据未完成 |
| 可清标 | 清标前置条件已满足 |
| 已清标 | 已生成有效清标结果 |
| 可定标 | 已选择有效清标情景 |
| 已完成 | 已生成定标和报告 |
| 结果失效 | 上游数据发生变化，需要重新测算 |

### 6.2 项目概览

#### 页面目标

让用户快速判断项目准备程度和当前测算结论。

#### 信息卡片

- 项目金额：最高投标限价、不可竞争费、可竞争金额。
- 数据准备：候选单位数、履约匹配成功数、异常数。
- 清标状态：四种K2情景完成情况。
- 定标状态：已完成预测组数。
- 最近测算：时间、执行人、规则版本。

#### 待办提示

按照优先级展示：

- 缺少必填参数。
- 候选单位报价或评分不完整。
- 履约信息匹配失败。
- K2情景未配置。
- 上游数据已修改，结果失效。
- 计算规则版本已更新，需要重新测算。

### 6.3 参数设置

#### 页面布局

使用三个表单卡片，不再像 Excel 一样放在同一个大表内：

1. 项目基本信息
2. 清标参数
3. 定标参数

#### 项目基本信息

| 字段 | 控件 | 校验 |
|---|---|---|
| 项目名称 | 文本框 | 必填 |
| 最高投标限价 | 金额输入 | 大于0 |
| 不可竞争费 | 金额输入 | 大于等于0且小于限价 |
| 可竞争金额 | 只读 | 限价减不可竞争费 |
| 项目类型 | 多选框 | 至少选择1项 |

#### 清标参数

- 总投标报价满分
- 排名递减扣分值
- 同类业绩评分上限
- 其他主客观评分上限
- 商标优、技术优是否启用及其评分方式（规则确认后显示）

#### 定标参数

以三行显示三个定标抽值：

| 抽值名称 | 比例 | 状态 |
|---|---:|---|
| 定标抽值1 | 百分比输入 | 已配置/缺失 |
| 定标抽值2 | 百分比输入 | 已配置/缺失 |
| 定标抽值3 | 百分比输入 | 已配置/缺失 |

比例输入框中输入 `1`，界面显示 `1%`，保存时转换为 `0.01`。

#### 保存交互

- “保存草稿”：允许保存未完整数据。
- “保存并校验”：保存后执行完整校验。
- 修改已测算参数时弹出提示：“保存后，现有清标和定标结果将失效。”

### 6.4 候选单位

#### 页面目标

维护当前项目的全部候选单位及投标数据。

#### 页面结构

```text
候选单位（共 X 家）                   + 新增单位  批量导入
┌───────────────────────────────────────────────────────────┐
│单位名称│投标总价│净下浮率│商标优│技术优│同类业绩│其他分│操作│
├───────────────────────────────────────────────────────────┤
│ ...                                                       │
└───────────────────────────────────────────────────────────┘
```

#### 交互规则

- 支持行内编辑或右侧抽屉编辑。
- 单位名称从单位库搜索选择。
- 无匹配单位时可在有权限的情况下新建单位。
- 输入投标总价后自动计算净下浮率。
- 若允许手工修改净下浮率，应实时提示与报价反算结果的差异。
- 得分超过参数上限时阻止保存。
- 删除单位前显示其参与的清标情景，并要求确认。

#### 表格辅助功能

- 搜索单位名称。
- 按投标总价、净下浮率排序。
- 展示数据完整性状态。
- 固定单位名称和操作列。
- 支持下载、导入标准模板（是否纳入MVP待确认）。

### 6.5 履约信息

履约数据属于跨项目基础数据，项目页面主要负责匹配和查看；维护入口放在独立的“履约数据库”。

#### 项目内履约匹配页

| 单位名称 | 项目类型 | 最近12季度数 | 履约结果 | 匹配状态 | 操作 |
|---|---|---:|---:|---|---|
| 单位A | 幕墙、装修 | 12/12 | 92.50 | 正常 | 查看明细 |
| 单位B | 幕墙 | 8/12 | -- | 数据不足 | 补录 |

#### 履约明细抽屉

- 展示每个项目类型的季度记录。
- 突出显示实际参与计算的最近12季度。
- 展示每季度权重。
- 展示单类型结果和跨类型汇总过程。

#### 履约数据库页面

后端按“单位ID + 项目类型 + 年度 + 季度”保存，前端可以提供两种查看方式：

- 明细模式：每行一个季度，适合维护和导入。
- 矩阵模式：每列一个季度，适合业务人员对比。

矩阵模式只是展示方式，不能把季度永久存为数据库字段。

### 6.6 清标测算

#### 页面分区

```text
┌────────────────────────────────────────────────────────────┐
│ 前置检查：参数 ✓  候选单位 ✓  履约数据 !  规则版本 Vx.x  │
├────────────────────────────────────────────────────────────┤
│ 情景配置                                                   │
│ [K2=0%] [K2=1%] [K2=2%] [K2=3%]                           │
│ 参与单位：多选                                             │
│ 平均报价：--   K1：--   评审基准价：--                    │
├────────────────────────────────────────────────────────────┤
│                              保存配置  执行清标测算         │
├────────────────────────────────────────────────────────────┤
│ 测算结果                                                   │
└────────────────────────────────────────────────────────────┘
```

#### 前置检查区

展示所有阻止测算的问题。问题项可点击跳转到对应页面和字段。

#### 情景配置区

- 以四个标签页或四张卡片展示K2情景。
- 单位选择使用可搜索多选框。
- 支持“全选”“清空”“复制上一情景配置”。
- 展示已选单位数和所选单位平均报价。
- K2数学作用未确认前，页面标记“规则待确认”，正式环境不允许执行。

#### 清标按钮

状态：

| 状态 | 表现 |
|---|---|
| 前置数据不完整 | 禁用，并显示缺失项 |
| 配置未保存 | 提示先保存或“保存并测算” |
| 可测算 | 主按钮可点击 |
| 计算中 | 显示加载状态，禁止重复提交 |
| 已测算 | 显示“重新测算” |
| 上游数据变化 | 显示“结果已失效，重新测算” |

#### 清标结果总览

首先展示四种情景对比：

| 情景 | 平均报价 | K1 | 评审基准价 | 前五单位 | 广田排名 |
|---|---:|---:|---:|---|---:|
| K2=0% |  |  |  |  |  |
| K2=1% |  |  |  |  |  |
| K2=2% |  |  |  |  |  |
| K2=3% |  |  |  |  |  |

点击某个情景进入明细表：

| 排名 | 单位 | 报价 | 净下浮率 | 履约结果 | 履约得分 | 报价差值 | 报价排名 | 报价得分 | 同类业绩 | 其他分 | 总分 |
|---:|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|

#### 查看计算过程

点击任一计算值，打开计算抽屉：

```text
报价得分：38.00
公式：MAX(0, 报价满分-(排名-1)×递减扣分)
输入：报价满分=40，排名=2，递减扣分=2
计算：40-(2-1)×2=38
规则版本：V1.0
```

#### 清标结论

系统自动生成四种情景的前五单位文字结论。我方单位使用主题强调色和“我方”标签，不只依赖红色表达。

### 6.7 定标预测

#### 前置选择

页面顶部选择一个有效的清标情景：

```text
清标K2：[0% ▼]
清标结果版本：2026-08-18 10:30 / V3
```

如果清标结果已失效，禁止执行定标并引导重新清标。

#### 入围单位预览

使用三个标签页：

```text
[N=5] [N=4] [N=3]
```

每个标签页展示当前入围单位、清标排名、报价、净下浮率和定标K1。

#### 九组结果矩阵

```text
┌──────┬──────────────┬──────────────┬──────────────┐
│      │ 定标抽值1    │ 定标抽值2    │ 定标抽值3    │
├──────┼──────────────┼──────────────┼──────────────┤
│ N=5  │ 单位A中标    │ 单位B中标    │ 单位A中标    │
│ N=4  │ 单位A中标    │ 单位A中标    │ 单位C中标    │
│ N=3  │ 单位B中标    │ 单位A中标    │ 单位A中标    │
└──────┴──────────────┴──────────────┴──────────────┘
```

每个结果卡片显示：

- 定标K1
- 定标抽值
- M值
- 预测中标单位
- 中标单位投标总价
- 与M值的差额

点击卡片查看所有入围单位的差额和排名。

#### 定标按钮

- 第一次执行显示“执行定标预测”。
- 已有结果时显示“重新预测”。
- 规则或上游数据变化后显示“结果已失效”。
- M值公式未冻结时，正式环境禁止执行，仅测试环境允许使用标记为“试算”的规则版本。

### 6.8 结果报告

#### 报告总览

顶部指标卡：

- 参与候选单位数
- 清标情景数
- 定标预测组数
- 我方单位最高模拟中标率

#### 报告内容

1. 项目基本信息。
2. 计算参数及规则版本。
3. 候选单位输入数据快照。
4. 四种清标情景对比。
5. 清标前五单位结论。
6. 九组定标预测矩阵。
7. 各单位中标次数及中标率。
8. 我方单位专项结论。

#### 中标率视图

分别展示，避免口径混淆：

- 固定清标K2和N下：分母3。
- 固定清标K2下：分母9。
- 全部清标情景：分母36。

最终启用哪些口径由业务确认。

#### 导出

- 导出Excel：适合复核全部明细。
- 导出PDF：适合评审和归档。
- 导出前展示报告预览。
- 报告带项目、测算时间和结果版本。

### 6.9 测算历史

#### 页面目标

保留每次计算的输入快照和结果，避免数据修改后无法追溯。

#### 列表字段

- 测算版本
- 测算类型：清标/定标
- 清标K2
- 执行人
- 执行时间
- 规则版本
- 当前状态：有效/失效
- 操作：查看、对比、导出

#### 版本对比

支持比较两个版本的：

- 参数变化
- 候选单位变化
- 报价和评分变化
- 清标排名变化
- 中标结果变化

## 7. 页面间数据关系

| 来源页面 | 数据 | 目标页面 | 使用方式 |
|---|---|---|---|
| 参数设置 | 限价、不可竞争费、项目类型 | 履约、清标、定标 | 匹配和计算 |
| 参数设置 | 清标评分参数 | 清标测算 | 得分计算 |
| 参数设置 | 三个定标抽值 | 定标预测 | M值计算 |
| 候选单位 | 单位、报价、净下浮率、评分 | 清标测算 | 生成单位结果 |
| 履约信息 | 最近12季度结果 | 清标测算 | 计算履约得分 |
| 清标测算 | 指定K2的总分和排名 | 定标预测 | 生成前N入围方案 |
| 定标预测 | 九组中标结果 | 结果报告 | 中标率和专项结论 |

## 8. 结果失效规则

以下任一变化应使清标和定标结果失效：

- 最高投标限价、不可竞争费或项目类型变化。
- 清标评分参数变化。
- 候选单位新增、删除。
- 投标报价、净下浮率或评分变化。
- 参与计算的履约数据变化。
- 清标情景参与单位变化。
- 清标计算规则版本变化。

以下变化只使定标结果失效：

- 三个定标抽值变化。
- 选择的清标K2变化。
- 定标规则版本变化。

失效只影响结果状态，不删除历史记录。

## 9. 前后端功能边界

### 9.1 前端负责

- 表单和表格交互。
- 百分比、金额展示格式。
- 基础即时校验。
- 测算状态和进度展示。
- 结果可视化和计算过程展示。

### 9.2 后端负责

- 业务数据最终校验。
- 履约最近12季度计算。
- 清标和定标计算。
- 排名和同分规则。
- 输入、规则和结果版本管理。
- 结果失效判断。
- 报告数据生成。

关键公式不得只写在前端，避免不同页面产生不同结果。

## 10. 接口草案

接口命名可根据最终技术栈调整。

| 方法 | 接口 | 用途 |
|---|---|---|
| GET | `/api/projects` | 项目列表 |
| POST | `/api/projects` | 创建项目 |
| GET/PUT | `/api/projects/{id}` | 项目详情及更新 |
| GET/PUT | `/api/projects/{id}/parameters` | 项目参数 |
| GET/POST | `/api/projects/{id}/bidders` | 候选单位列表及新增 |
| PUT/DELETE | `/api/projects/{id}/bidders/{bidderId}` | 修改、删除候选单位 |
| GET | `/api/projects/{id}/performance-summary` | 项目单位履约匹配结果 |
| GET/POST | `/api/performance-records` | 履约记录查询及新增 |
| PUT | `/api/projects/{id}/clear-scenarios` | 保存四种清标配置 |
| POST | `/api/projects/{id}/clear-calculations` | 执行清标测算 |
| GET | `/api/projects/{id}/clear-calculations/{version}` | 清标结果 |
| POST | `/api/projects/{id}/award-calculations` | 执行定标预测 |
| GET | `/api/projects/{id}/award-calculations/{version}` | 定标结果 |
| GET | `/api/projects/{id}/reports/{version}` | 报告数据 |
| POST | `/api/projects/{id}/reports/{version}/exports` | 生成导出文件 |
| GET | `/api/projects/{id}/calculation-history` | 测算历史 |

计算接口应返回：

- 结果版本
- 输入版本
- 规则版本
- 全部中间值
- 警告信息
- 最终排名或中标结果

## 11. 页面状态设计

每个业务页面都应覆盖：

- 首次空状态：说明下一步需要做什么。
- 加载状态：骨架屏或进度提示。
- 保存成功：明确提示保存时间。
- 校验失败：定位到字段或单位。
- 计算失败：提供可理解的业务原因和错误编号。
- 无权限：只读展示或提示联系管理员。
- 结果失效：保留旧结果但禁止继续作为下游输入。

## 12. 关键交互验收

1. 用户不需要编辑公式即可新增任意数量候选单位。
2. 输入报价后能够自动得到净下浮率，并查看计算过程。
3. 履约页面能够清楚区分匹配成功、数据不足和未匹配。
4. 清标前置条件不满足时按钮不可执行，并可跳转修复。
5. 每种清标情景可以查看独立的平均报价、K1、排名和前五。
6. 定标页面能够一次展示N=5、N=4、N=3和三个抽值形成的9组结果。
7. 点击任何得分、M值或排名能够查看输入和公式。
8. 上游数据变化后结果立即标记失效，但历史版本仍可查看。
9. 页面结果与导出报告完全一致。
10. 我方单位统一使用 `isOurCompany` 识别，并在相关结果中突出展示。
